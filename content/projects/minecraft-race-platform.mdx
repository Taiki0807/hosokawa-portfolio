## 概要

Minecraft Race Platformは、複数人でエンダードラゴン討伐RTAを競うプラットフォームです。管理者がWeb画面から試合を作成すると、自宅のKubernetes（k3s）クラスタ上でMinecraftサーバーが動的に立ち上がり、試合終了後は自動的に破棄されます。観戦者はライブで進捗やイベント（ネザー到達、ドラゴン討伐など）をリアルタイムに追えます。

## アーキテクチャ

![Minecraft Race Platform ネットワーク構成図](/project-images/minecraft-race-platform-network.png)

```text
Web
Next.js 16
  ├─ React 19 / TypeScript
  ├─ Tailwind CSS v4 / shadcn/ui
  └─ Supabase Auth / Postgres / RLS
            ↓
自宅サーバー
Go Race Controller
  ├─ ServiceAccount / RBAC
  └─ Kubernetes API
            ↓
k3s / Race専用Worker
  ├─ mc-router
  ├─ Paper Minecraft Pods
  ├─ 自作Paper Plugin
  └─ local-path PVC

Minecraft通信
Client → VPS/Nginx → Tailscale → mc-router → Paper Pod
```

Web側（Next.js / Supabase）と自宅サーバー側（Go / Kubernetes / Minecraft）は完全に切り離されており、Tailscaleを介してのみ接続しています。

## 技術的なアピールポイント

### 1. 試合ごとにMinecraft環境を自動生成

単一のMinecraftサーバーを使い回すのではなく、試合単位で以下のKubernetesリソースを動的に作成します。

- Deployment
- Service
- PVC
- 接続先ホスト名
- 大会IDなどの環境変数

参加者ごとに独立した環境を提供でき、試合終了後の停止や削除までRace Controllerで管理できます。

### 2. Kubernetes Operatorに近い制御をGoで実装

Go APIは単なるCRUDではなく、ユーザーの操作をKubernetesリソースへ変換します。

```text
大会開始API
  → Kubernetesリソース生成
  → Pod起動確認
  → 接続先発行
  → RUNNINGへ状態更新
```

アプリケーションとインフラを連携させた、Platform Engineering寄りの実装です。

### 3. MinecraftとWebをリアルタイム連携

自作Paperプラグインで、次の情報を収集する設計です。

- プレイヤーの参加・退出
- 死亡
- ネザー／エンドへの到達
- Advancementの進行
- ブレイズロッドなどの所持数
- エンダードラゴン討伐
- ゴール時間

ゲーム内イベントを認証付きHTTPでGo APIへ送り、ライブ順位やイベント履歴へ反映します。

### 4. 自宅環境を実用的なプラットフォームとして構築

Proxmox上にk3sクラスタを構築し、Terraform、Helm、Kubernetesを組み合わせています。単にMinecraftを動かすだけではなく、Webサービスから動的にゲーム基盤を制御できる構成です。

### 5. 自宅サーバーを安全に外部公開

<Callout type="info">
  k3sを直接インターネットへ公開せず、VPSと自宅環境をTailscaleで接続しています。公開部分と内部クラスタを分離した構成です。
</Callout>

```text
インターネット
  → Cloudflare DNS
  → VPS・Nginx
  → Tailscale
  → 自宅k3s
```

### 6. 再起動後も試合状態を復元

試合情報、イベント、進捗をConfigMapへ保存し、Race Controller再起動後も以下を復元できるところまで確認済みです。

- 試合ステータス
- イベント履歴
- エンダードラゴン討伐状態
- プレイヤー順位

一時的なメモリ管理だけで終わらず、障害や再起動を考慮した設計になっています。
